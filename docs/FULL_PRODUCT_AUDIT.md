# 奇遇AI全量产品审计与重构基线

审计日期：2026-07-16

## 结论

原软件不是一个单纯网页，而是“网页控制台 + 服务端任务调度 + Windows 桌面执行器 + 微信/内容平台自动化”的组合产品。原用户端共有 31 条业务路由，左侧主导航只展示高频入口，其他能力藏在二级、三级页面中。

奇遇AI当前已经接通 GPT 文案与生图、Seedance 2.0、媒体上传、电商生图、公域公开线索采集、AI筛选、微信联系人同步、消息识别/草稿/授权发送和设备任务回写。34 个现有业务入口均已具备真实页面、真实数据状态或明确的外部服务配置提示；首页、作品库、素材库、任务与设备统计均读取服务器数据。当前剩余事项主要是第三方平台首次登录/验证码、ASR/TTS 外部服务、支付计费、客户多租户体系以及正式代码签名，而不是页面占位问题。

## 统一运行架构

1. 网站负责：客户操作界面、数据保存、AI调用、任务编排、审核、状态与日志。
2. 云端模型负责：文案、意图评分、专家回复、图片、视频、后续 ASR/TTS。
3. 电脑助手负责：访问已登录的微信和内容平台、读取用户授权的可见界面、执行用户确认的任务、回传结果。
4. 对象存储负责：图片、视频、音频和文档文件。
5. 所有统计只读取真实记录；没有数据时显示 0；没有配置时显示“需要配置”，不再用演示数字冒充结果。

## 自动化边界

- 可以实现：联系人同步、AI辅助回复、受控自动发送、公开页面线索收集、内容发布、任务回写、失败重试。
- Mac 已完成真实联系人、未读消息、草稿和任务回写验证；Windows 自动化组件与安装包已经封装并通过文件完整性检查，仍需在一台真实 Windows 电脑上做微信与平台端到端验收。
- 不复刻：绕过平台风控、验证码规避、批量骚扰、抓取非公开数据、未经授权的隐蔽控制。
- 客户正式商用前还需要：客户登录与租户隔离、套餐计费、隐私协议、操作审计和 Windows 安装包签名。
