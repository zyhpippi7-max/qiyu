# 奇遇AI产品与技术实施总计划

版本：v1.0

规划日期：2026-07-20
核心方向：个人微信桌面端 AI 私域助手

## 1. 产品结论

奇遇AI不应该继续以“功能很多的AI工具箱”作为第一定位。最有差异化、最有商业价值的主产品应当是：

> 运行在客户自己 Mac 或 Windows 电脑上的个人微信 AI 私域助手。它能理解最近聊天、客户资料和企业知识，辅助或受控地完成回复、跟进、群发、标签和朋友圈运营。

产品的第一卖点不是“自动点击微信”，而是：

1. 知道正在和哪个客户聊什么。
2. 知道公司的产品、价格、政策和禁忌。
3. 知道销售当前应该推进哪一步。
4. 能生成符合指定角色、可直接发送的回复。
5. 在得到授权后，由本地电脑完成实际操作。
6. 全程可暂停、可审核、可追踪、可复盘。

内容创作、公域获客、平台发布仍然保留，但它们应该服务于同一条业务闭环：

```text
公域发现线索
  → 人工审核
  → 导入个人微信客户池
  → AI理解对话并跟进
  → 朋友圈和内容持续触达
  → 成交、复购、召回
  → 数据复盘
```

## 2. 产品边界

### 2.1 必须做到

- 支持个人微信桌面端，而不是只支持企业微信。
- Mac 和 Windows 分别维护可靠的本地执行器。
- 登录态、Cookie、微信窗口操作保留在客户电脑。
- 支持读取用户授权后可见的最近 30～50 条文字聊天。
- 支持客户标签、客户阶段、企业知识库和 AI 回复角色。
- 默认只生成草稿，自动发送必须显式开启并限定范围。
- 每一步有任务状态、失败原因、重试和人工接管入口。
- 同一条消息不得重复回复。
- 联系人不确定、界面异常、识别置信度低时必须停止。

### 2.2 明确不做

- 不注入微信进程。
- 不破解微信通信协议。
- 不读取或上传未经授权的隐藏数据库。
- 不绕过验证码、登录保护或平台风控。
- 不提供“防封参数”“养号脚本”或无差别骚扰。
- 不承诺个人微信自动化永远不受微信版本变化影响。
- 不在没有二次校验的情况下自动点击发送。

## 3. 现有系统真实完成度

目前代码已经具备下列基础，不是从零开发：

### 3.1 已具备的服务端基础

- 账号登录、管理员、普通会员和套餐。
- 设备注册、设备令牌、心跳和在线状态。
- 自动化任务创建、领取、执行、回报、失败和重试。
- 私域联系人、标签、方案、步骤和运行记录。
- 企业知识条目读取和简单相关性检索。
- 客户标签与最近跟进资料组装。
- 最近聊天 + 客户资料 + 企业知识 + 角色提示词生成回复。
- 自动回复计划、每日上限和重复消息指纹。
- 公域线索、AI评分、去重和人工审核。
- 图片、视频、媒体和通用业务记录。

### 3.2 已具备的桌面端基础

- Electron Mac/Windows 客户端。
- 新域名 `https://xcx.qiyuai.com.cn`。
- 两秒一次的任务领取和执行结果回传。
- Mac 辅助功能、屏幕录制和稳定权限助手。
- Mac 微信联系人、未读会话、聊天 OCR、草稿和发送。
- Windows PowerShell/UI Automation 微信辅助组件。
- 30～50 条上下文读取任务类型。
- AI 回复任务类型。
- 抖音、小红书、快手、视频号本地登录窗口。
- 本地目录授权与文件索引。

### 3.3 当前不能视为商用完成的部分

- 未读消息识别容易受微信窗口大小、主题和界面更新影响。
- 聊天气泡方向目前主要按屏幕位置判断，群聊和特殊消息可能误判。
- 搜索联系人后缺少足够严格的会话标题二次校验。
- 用户手动操作微信时，自动化可能抢占焦点。
- 发送前缺少“联系人 + 最后一条消息 + 回复任务”三重校验。
- 图片、语音、文件、引用消息和小程序卡片尚未形成可靠语义输入。
- Windows 需要在真实 Windows 10/11 和多个微信版本上端到端验收。
- 很多非私域页面有界面或数据保存，但没有完整业务闭环。
- 多租户隔离、企业工作空间、正式计费和商业审计还不完整。
- Mac 和 Windows 正式签名、自动更新和崩溃恢复仍需商用化。

## 4. 目标系统架构

### 4.1 云端控制面

云端负责：

- 用户、企业工作空间和权限。
- 联系人业务资料、标签和客户阶段。
- 企业知识库和 AI 专家。
- 自动回复、群发、SOP 和朋友圈计划。
- AI 推理、审核队列、任务调度和结果汇总。
- 运营数据、审计日志和管理员后台。

### 4.2 本地执行面

奇遇AI电脑助手负责：

- 检查微信是否安装、运行和登录。
- 检查系统授权和微信界面兼容性。
- 检测未读会话。
- 打开并验证目标联系人。
- 读取当前可见聊天记录。
- 执行草稿填入、发送、朋友圈打开和平台发布准备。
- 保存本地登录态和本地自动化日志。
- 在断网时暂存任务结果，恢复后回传。

### 4.3 本地隐私数据库

桌面端新增加密本地数据库，用于保存：

- 微信账号本机标识。
- 最近处理过的消息指纹。
- 本地会话摘要和短期上下文缓存。
- 自动化坐标、选择器版本和兼容性信息。
- 待回传结果和离线任务日志。
- 本地授权状态。

默认不长期保存完整聊天原文。云端默认只保存：

- AI生成的回复。
- 客户摘要和业务标签。
- 任务状态和必要审计信息。

企业可选择开启“云端会话原文同步”，但必须单独告知并获得授权。

## 5. 个人微信 AI 自动回复核心引擎

### 5.1 本地状态检测器

启动时按顺序检测：

1. 奇遇AI版本是否最新。
2. 设备是否已绑定当前工作空间。
3. Mac辅助功能和屏幕录制是否有效。
4. Windows UI Automation组件是否完整。
5. 微信是否安装、运行并完成登录。
6. 当前微信版本是否在已验证兼容列表内。
7. 窗口是否可识别、缩放比例是否支持。
8. 本地自动回复是否处于开启时段。

界面必须显示明确状态，不能只显示“在线”：

- 设备在线
- 微信已登录
- 权限正常
- 消息监听正常
- 当前模式
- 最后成功处理时间
- 最近错误

### 5.2 会话观察器

第一版采用受控轮询：

- 空闲时每 5～10 秒检查一次。
- 用户正在操作微信时暂停。
- 检测到未读后只处理一个会话。
- 完成或失败后再处理下一个会话。
- 微信最小化、锁屏或远程桌面异常时停止。

后续可增加系统通知辅助判断，但不能依赖通知读取全部内容。

### 5.3 联系人验证器

每次打开联系人必须验证：

- 搜索词与会话标题一致。
- 备注名、昵称和内部联系人记录能够对应。
- 群聊必须识别群名称和成员数量。
- 文件传输助手、公众号、服务通知默认排除。
- 重名联系人必须要求用户预先绑定唯一身份。

发送前再次读取顶部标题。如果标题变化，任务立即失败，不执行发送。

### 5.4 聊天上下文读取器

目标是读取最近 30～50 条业务相关信息，而不是简单截一张图。

处理流程：

1. 打开目标会话。
2. 识别聊天区域边界。
3. 从最新消息向上分页。
4. 对每页执行 OCR 或可访问性元素读取。
5. 根据气泡位置、颜色、头像区域和 UI 元素判断方向。
6. 合并被换行拆开的同一条消息。
7. 去除时间、系统提示和重复截图内容。
8. 保留消息顺序。
9. 标记识别置信度。
10. 低置信度时不自动发送。

第一版支持：

- 普通文字
- 表情文字描述
- 引用消息中的可见文字

第二版支持：

- 语音转写
- 图片文字 OCR
- 图片内容理解
- 文件名和文件类型
- 小程序、链接和商品卡片摘要

### 5.5 客户记忆系统

每个客户形成一张动态客户卡片：

- 基础身份：昵称、备注、来源、负责人。
- 标签：意向产品、地区、行业、渠道。
- 生命周期：新线索、已加好友、咨询、报价、考虑、成交、复购、流失。
- 最近关注点。
- 已提供的报价或方案。
- 客户明确表达的需求和异议。
- 下一步承诺和跟进时间。
- 风险：投诉、退款、敏感、需人工。
- AI自动生成的会话摘要。

每次成功对话后更新摘要，不需要每次都把全部历史长期上传给模型。

### 5.6 知识检索

知识库拆分为：

- 产品资料
- 价格与套餐
- 库存与交付
- 常见问题
- 销售话术
- 售后政策
- 禁止承诺
- 活动规则
- 公司介绍
- 成功案例

知识条目必须增加：

- 生效时间和失效时间。
- 适用产品。
- 适用客户类型。
- 权限范围。
- 来源文件。
- 最后审核人。

AI回复时只召回与当前问题有关的知识。价格、优惠、退款、库存等高风险内容必须要求精确知识命中，否则转人工。

### 5.7 AI回复决策器

输入：

- 最近聊天。
- 客户卡片。
- 企业知识。
- 指定AI专家。
- 当前业务目标。
- 回复长度和风格。
- 安全规则。

输出不应只有一段文字，而应包含结构化结果：

```json
{
  "intent": "询价",
  "customerStage": "考虑",
  "riskLevel": "medium",
  "suggestedAction": "确认使用人数后报价",
  "reply": "可以的，方便问一下您计划几个人使用吗？我按实际人数给您核算合适的方案。",
  "knowledgeIds": [12, 19],
  "needsHuman": false,
  "confidence": 0.91
}
```

只有 `needsHuman=false`、置信度达标且符合自动发送策略时，才允许进入自动发送。

### 5.8 三种执行模式

#### 建议模式

- 只在网站和桌面悬浮窗显示建议。
- 用户自行发送。
- 适合新客户首次使用。

#### 自动填入模式

- 自动找到联系人并填入草稿。
- 不点击发送。
- 用户检查后按回车。
- 应作为默认模式。

#### 白名单自动发送模式

- 只允许指定好友或指定标签。
- 只在指定时间段运行。
- 必须设置每日上限。
- 敏感意图自动转人工。
- 新联系人前若干次回复默认人工确认。

### 5.9 发送安全锁

发送动作前必须同时满足：

1. 任务仍然有效且未取消。
2. 当前联系人标题与任务目标一致。
3. 最后一条客户消息指纹仍然一致。
4. 没有检测到用户正在输入。
5. AI回复未触发敏感规则。
6. 当前联系人属于允许范围。
7. 没有超过每日和每小时上限。
8. 该消息未处理过。

发送后读取微信界面，确认消息确实出现在右侧；否则标记“发送结果不确定”，不自动重试。

## 6. 关键数据和接口改造

### 6.1 新增核心数据表

- `workspaces`：企业工作空间。
- `workspace_members`：成员和角色。
- `wechat_accounts`：微信账号与设备绑定，不保存密码。
- `wechat_contact_bindings`：微信可见名称与客户唯一记录的绑定。
- `customer_profiles`：客户阶段、摘要、负责人和下一步。
- `conversation_summaries`：会话摘要和最后消息指纹。
- `reply_policies`：自动回复范围、时段、上限和转人工规则。
- `reply_drafts`：AI回复、审核状态和最终发送内容。
- `follow_up_tasks`：承诺、预约和下次跟进。
- `knowledge_sources`、`knowledge_chunks`：知识来源与可检索片段。
- `automation_leases`：任务租约，防止重复领取。
- `automation_events`：每一步执行事件。
- `device_health`：权限、微信版本、窗口兼容性和错误。
- `approval_queue`：手机和网页统一审核队列。
- `audit_logs`：管理员、AI和设备动作审计。

### 6.2 自动化任务协议

任务状态统一为：

```text
draft
→ awaiting_approval
→ queued
→ leased
→ prechecking
→ reading_context
→ generating
→ verifying
→ drafting/sending
→ succeeded
```

失败状态区分：

- `blocked_permission`
- `blocked_login`
- `blocked_user_active`
- `blocked_low_confidence`
- `blocked_policy`
- `failed_ui_changed`
- `failed_network`
- `failed_unknown`
- `result_uncertain`

每个任务增加：

- 幂等键。
- 租约到期时间。
- 最大重试次数。
- 当前步骤。
- 联系人验证信息。
- 触发消息指纹。
- 人工审批人。
- 执行截图或局部证据路径。

### 6.3 API分层

- `/api/devices/*`：绑定、心跳、健康和版本。
- `/api/automation/*`：领取、续租、取消、回报。
- `/api/wechat/contacts/*`：联系人导入、绑定、去重。
- `/api/wechat/conversations/*`：摘要、待处理和跟进状态。
- `/api/replies/*`：生成、审核、改写、发送。
- `/api/policies/*`：自动回复安全策略。
- `/api/knowledge/*`：文件、解析、检索和版本。
- `/api/approvals/*`：网页和移动端审核。
- `/api/admin/*`：用户、套餐、权限、审计。

旧的 `/api/automation` 在迁移期间保留兼容层，桌面端升级完成后再拆分。

## 7. 全局界面与交互规范

### 7.1 布局

- 正常内容最大宽度根据屏幕在 1280～1680px 之间自适应。
- 不能再整体缩放整个网页来适配屏幕。
- 字号使用可读的响应式范围，正文最低不小于 14px。
- 弹窗使用 `position: fixed` 和视口居中。
- 弹窗最大高度为视口减安全边距，内容区独立滚动。
- 弹窗标题和底部操作固定，不允许被顶部裁切。
- 低分辨率屏幕自动切换单列布局。
- 所有选择客户的界面共用同一个客户选择器。

### 7.2 统一客户选择器

所有私域模块统一使用：

- 搜索昵称、备注和标签。
- 最近联系人。
- 按标签筛选。
- 按客户阶段筛选。
- 排除黑名单、已退订和高风险客户。
- 全选当前筛选结果，而不是全选所有人。
- 已选客户独立区域。
- 支持保存人群。
- 1200人以上使用虚拟列表和服务端搜索。
- 显示预计人数、重复人数和不可执行人数。

### 7.3 统一任务详情抽屉

任何任务点击后显示：

- 业务名称。
- 创建人。
- 执行设备。
- 当前步骤。
- 目标客户。
- AI使用的知识。
- 生成内容。
- 执行日志。
- 错误原因。
- 重试、取消、转人工。

## 8. 每个主页面和子界面的改造计划

## 8.1 AI指挥中心

定位：产品总入口，不再只是展示数据。

子界面：

- 今日待处理客户。
- AI建议回复。
- 待审核任务。
- 超时未回复。
- 今日跟进和预约。
- 设备健康。
- 最近执行失败。
- 一句话创建任务。

改动：

- 首页第一屏突出“微信AI助手是否正常工作”。
- 显示正在监听的微信账号和当前模式。
- 快捷操作改为“处理未读、审核回复、创建群发、查看风险客户”。
- 内容创作入口放到第二层。

优先级：P0。

## 8.2 数据分析

定位：查看私域经营效果，而不是展示虚构粉丝数字。

子界面：

- 回复量和平均响应时间。
- AI建议采纳率。
- 自动发送成功率。
- 转人工率。
- 客户阶段变化。
- 跟进完成率。
- 群发触达和回复。
- 知识命中与知识缺口。
- 设备成功率。

实现：

- 所有指标从消息、任务、审核和客户阶段事件聚合。
- 可按员工、微信账号、标签、计划和时间筛选。

优先级：P1。

## 8.3 智能体

定位：直接测试AI角色和知识，而不是单独的聊天玩具。

子界面：

- 角色测试。
- 指定客户模拟。
- 知识命中查看。
- 工具调用记录。
- 回复对比。

改动：

- 可以选择某位客户，用其脱敏摘要模拟回复。
- 显示引用知识来源。
- 一键将满意回复保存为范例。

优先级：P1。

## 8.4 自动工作流

定位：跨模块通用流程，微信SOP仍保留专用简化页面。

触发器：

- 新增客户。
- 收到新消息。
- 客户标签变化。
- 到达跟进时间。
- 群发完成。
- 内容审核通过。

动作：

## 9. 建议新增的差异化功能

### 9.1 AI回复悬浮助手

在微信窗口旁显示一个小型悬浮条：

- 生成回复。
- 更简短。
- 更专业。
- 更有成交推动力。
- 填入草稿。

不需要用户频繁切换网页，是最直接的体验提升。

### 9.2 下一步最佳动作

AI除了写回复，还给销售一个建议：

- 继续提问。
- 发产品资料。
- 给报价。
- 邀请通话。
- 明日跟进。
- 转售后。

### 9.3 承诺自动识别

从聊天中识别：

- “明天联系我”
- “下午发报价”
- “月底再看”
- “有货通知我”

自动创建跟进提醒，避免丢单。

### 9.4 高意向和流失雷达

根据聊天变化识别：

- 询价。
- 多次追问。
- 提到竞品。
- 长时间未回复。
- 明显不满。
- 曾经成交但长期沉默。

### 9.5 知识缺口

AI无法可靠回答的问题自动汇总：

- 问题原文。
- AI缺少的知识。
- 出现次数。
- 建议新增的知识条目。

这会持续提升自动回复质量。

### 9.6 销售教练

对人工聊天进行复盘：

- 是否及时回应。
- 是否理解需求。
- 是否过早报价。
- 是否遗漏下一步。
- 推荐更好的回复。

### 9.7 回复风格学习

用户选择“这条像我”“这条不像我”，逐步形成个人语气档案。只学习被确认的回复，不直接学习所有历史消息。

### 9.8 对话模拟测试

上线自动回复策略前，用典型客户问题进行批量模拟，检查：

- 是否引用错误价格。
- 是否承诺过度。
- 是否语气合适。
- 是否应该转人工。

### 9.9 自动化回放与诊断

失败后保留脱敏局部证据：

- 微信窗口尺寸。
- 识别到的标题。
- OCR结果。
- 失败步骤。
- 客户端和微信版本。

管理员可以快速判断是权限、界面还是网络问题。

### 9.10 每日老板报告

每天生成：

- 今日新增客户。
- 待回复。
- 高意向。
- 成交机会。
- 风险客户。
- AI处理量。
- 人工接管量。
- 设备异常。

### 11.1 本地自动化回归场景

- 询价。
- 售后。
- 投诉。
- 退款。
- 库存未知。
- 对方表达模糊。
- 聊天历史不足。

- 诱导AI编造。
- 敏感信息。

### 11.3 发布门槛

任何支持“自动发送”的版本必须满足：

- 目标联系人准确率达到内部商用门槛。
- 重复发送为零。
- 低置信度任务100%停止。
- 自动发送有完整日志。
- 一键暂停在本机立即生效。
- 新版本可以回滚。

## 12. 自动更新与发布

### 12.1 更新策略

- Mac和Windows分别建立稳定版、灰度版。
- 客户端启动后检查版本。
- 下载后校验签名和哈希。
- 空闲时安装。
- 更新失败保留旧版本。
- 自动化核心变化先灰度到内部设备。

### 12.2 兼容性配置

服务器保存：

- 客户端最低版本。
- 支持的微信版本。
- OCR/选择器配置版本。
- 已知问题。
- 是否暂停某项高风险动作。

微信升级导致识别异常时，可以远程关闭自动发送，而不是等待重新发安装包。

## 17. 最终产品形态

成熟后的奇遇AI不应只是一个网页，也不只是一个自动点击工具，而是四层产品：

1. **客户大脑**：客户标签、阶段、摘要、承诺和下一步。
2. **企业大脑**：产品、价格、政策、案例和回复规范。
3. **AI决策层**：判断意图、风险、回复和下一步动作。
4. **本地执行层**：在个人微信和内容平台完成用户授权的实际操作。

近期所有开发决策都应优先回答一个问题：

> 这项改动是否能让个人微信AI回复更准确、更安全、更稳定，或者让客户更容易完成成交和跟进？

如果答案是否定的，就不应排在核心链路之前。
