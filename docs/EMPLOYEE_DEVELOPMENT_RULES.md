# 员工开发规范与管理规则

## 一、任务领取

1. 先阅读本人专属任务文件和对应 Issue，但 Issue 只代表任务方向，不代表可以立即修改。
2. Codex 先做只读检查，输出预计修改效果、文件清单、风险和验收方法。
3. 员工把方案交给负责人，只有负责人明确回复“同意修改”后才能编辑源码。
4. 任务描述不清、未获得同意或需要越权时暂停，不自行猜测产品方向。

## 二、当前本地工作规则

- 员工只在自己的电脑上修改，不能直接编辑服务器文件。
- 当前禁止 `git commit`、`git push`、创建 PR、合并和发布。
- 修改完成后向负责人提供：页面截图、`git status`、`git diff --stat`、完整 `git diff` 和测试结果。
- 一次方案原则上不超过 5 个文件、300 行有效改动；超过则停止并申请拆分。
- 负责人看完本地结果后决定继续修改、撤销或由负责人统一提交。

## 三、Codex 操作规章

每次交给 Codex 的提示必须包含：

> 当前只做本地工作。先只读分析并列出修改方案、文件清单、风险和验收方法，等待负责人明确同意后再修改。只能完成分配任务和允许文件；不得 commit、不得 push、不得创建 PR、不得部署、不得连接服务器、不得修改 API/数据库/桌面自动化/依赖。完成本地修改和测试后停止，不处理顺手发现的问题。

员工必须检查 Codex 的 `git diff`，不能只看它的文字结论。出现下列情况立即停止：

- Codex 要求服务器、数据库或管理员密码；
- 准备修改未列入范围的文件；
- 准备升级包、重构架构或删除大量代码；
- 准备自动部署、推送主分支或合并 PR；
- 测试使用真实客户数据或准备发送真实微信消息。

## 四、交给负责人查看的本地验收包

1. 计划解决什么问题；
2. 实际修改了哪些文件；
3. `git diff` 的全部内容；
4. 测试命令及结果；
5. 修改前后截图；
6. 风险、未完成项和恢复方式。

负责人未看完以上内容前，员工和 Codex 不得提交、推送或创建 PR。

## 五、安全与保密

- 密码、密钥、客户信息、聊天记录和数据库内容不得发给 Codex、写入 Issue、截图或提交 Git。
- 本地环境变量只保存在被 `.gitignore` 排除的文件中。
- 禁止把源码复制到个人仓库、网盘或第三方 AI 平台。
- 发现疑似密钥泄漏立即停止操作并通知负责人，不自行隐藏或删除证据。

## 六、完成定义

任务只有同时满足以下条件才算完成：负责人先批准修改方案、功能符合任务、指定尺寸通过、测试通过、无越权文件、本地验收包完整、负责人最终验收通过。Codex 显示“完成”不等于任务完成。
